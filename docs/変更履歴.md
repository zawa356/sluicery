# 変更履歴

## [未リリース]

### 追加
- yt-dlp の venv 管理（`downloader/version.py`）：インストール・切替（`use`）・削除・状態判定（`ready`/`not_installed`/`broken`）・世代整理（`prune_old_versions`）。`fcntl.flock` で `app` サービス内の直列化、`os.symlink` + `os.replace` で `current` symlink を原子的に差し替える（D-011, D-012）
- `ytdlp_release` テーブルと Alembic マイグレーションを追加（D-011）
- yt-dlp CLI ラッパ（`downloader/ytdlp.py`）：`YtdlpRunner`。プロセスグループ単位のタイムアウト終了（アイドル/絶対/キャンセル）、stdout/stderr の並行読み取り、コマンドラインのマスク層（`mask_command_line`）
- 出力フレーミング規約（`downloader/protocol.py`）と進捗パーサ（`downloader/progress.py`）。パーサは壊れた入力でも例外を投げない
- エラー分類ルール（`downloader/errors.py`）：`ok`/`failed`/`unavailable`/`blocked`。未知のメッセージは安全側の `failed` に倒す（D-014）
- CLI に `ytdlp status/list/install/use/remove/exec/probe/fetch` サブコマンドを追加。`probe`/`fetch` は Phase 4 のオプション合成が入るまでの暫定実装（予約引数を直接指定）
- degraded 起動：`app` は yt-dlp 未導入でも起動し、`ytdlp.auto_install` が true なら非同期でベストエフォートに自動導入を試みる。`worker` は yt-dlp が `ready` になるまで待機ループへ入り、未実装の Task 処理（Phase 6）を待つ間も終了しない（D-013、旧: restart ループになっていた問題の修正でもある）
- `core/settings.py` の `CODE_DEFAULTS` に `ytdlp.*`（`auto_install`/`keep_versions`/`idle_timeout_sec`/`absolute_timeout_sec`/`discover_timeout_sec`/`term_grace_sec`/`stderr_tail_kb`）を追加
- Phase 3 のユニットテスト一式（`tests/test_ytdlp_version.py`、`test_ytdlp_runner.py`、`test_progress_parser.py`、`test_errors_classification.py`）。yt-dlp 実行を伴うものは疑似スクリプト（`tests/fixtures/fake_ytdlp.py`）でモックし、実ネットワークを使わない
- 開発依存の lock ファイル `requirements-dev.lock` と、Dockerfile の `test` ステージ（dev 依存込み）。`make test` はこのステージをビルドしてコンテナ内で pytest を実行する（本番 `runtime` ステージには dev 依存を焼き込まない。docs/phase3_指示書.md §0.1）
- Docker 環境を作成（Dockerfile。ベースイメージを digest 固定、rclone / ffmpeg を checksum 検証付きで導入。D-001, D-002）
- Makefile と compose.yaml を作成（app / worker-network / worker-compute の3サービス構成）
- entrypoint.sh を作成（PUID/PGID/UMASK 制御、`SECRET_KEY` 未設定時の起動拒否。D-001）
- `src/sluicery/` パッケージ骨格を作成（要件定義 §18 のディレクトリ構成、多くは空スタブ）
- ドキュメント体系を整備（AISTATE.md / docs/基本設計.md / docs/変更履歴.md / README.md / docs/footprint.md / docs/storage.md / docs/legal.md）
- 設定層 `config.py` を実装（Pydantic Settings、`SECRET_KEY` 検証、`config check` 用の全項目チェック）
- DB エンジン・セッション管理・PRAGMA 設定（`db/session.py`）
- 暗号化カラム型 `EncryptedJSON` と `SECRET_KEY` 指紋チェック（`db/crypto.py`。D-004）
- ORM モデル定義（要件定義 §7.1 の全12テーブル、`db/models.py`）
- Alembic セットアップと初期マイグレーション（`migrations/`）
- 設定アクセサ `core/settings.py`（既定値はコード側、`setting` テーブルは上書きのみ。D-005）
- リポジトリ層の基本 CRUD と `Task.claim_next()` のアトミック実装（`db/repositories/*`。D-006）
- CLI に `config check` / `db upgrade|current|revision` / `settings list|get|set|unset` を追加
- Phase 2 のユニットテスト一式（`tests/`）
- `requirements.lock` を生成（`make lock`）

### 変更
- `.env.example`: `AUTO_MIGRATE` を追加。`STAGING_WARN_PCT` 等の運用パラメータ項目を削除し `setting` テーブル側に移行（D-005）
- `compose.yaml`: `worker-network`/`worker-compute` の `depends_on` を単純な起動順序から `condition: service_healthy` に変更（`app` の `/healthz` 応答を待つ）
- README: セットアップ手順から `make lock` を外した（lock ファイルはコミット済みのため不要。依存更新時のみ実行する運用コマンドとして再掲）。`make` が無い環境向けに `docker compose up -d --build` の直接コマンドを併記

### 修正
- SQLite で `DateTime(timezone=True)` が tzinfo を保持しない問題を `UTCDateTime` 型で修正（D-007）
- `.env.example` の `SECRET_KEY` 生成例が Fernet の期待する形式でなかった問題を修正
- `.gitignore` のアンカー未指定（`data/` 等が任意階層にマッチしていた）を修正
- AISTATE.md の要件定義からの用語ドリフトを是正
- `MEDIA_ROOT`（ホスト側 bind mount パス）の存在・書き込み検証が、コンテナ内では存在しないホスト側パス文字列をそのままチェックしており、既定値以外の `MEDIA_ROOT` を設定すると起動できない問題を修正（`docker compose up` の実地検証で発覚。D-010）

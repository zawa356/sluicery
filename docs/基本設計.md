## 6. 外部依存（yt-dlp / rclone / ffmpeg）との境界

- yt-dlp: 永続 volume 上の venv にインストール。アプリイメージには焼き込まない（要件定義 §5）
- rclone / ffmpeg: イメージに焼き込む。バージョンは Dockerfile 内で明示固定
- いずれも CLI を subprocess 経由で呼び出す。Python API・shell 経由の呼び出しは行わない

## 7. 設計判断の記録

### D-001: 権限降格に gosu ではなく setpriv（util-linux）を使う

- 日付: 2026-08-08
- 背景: PUID/PGID/UMASK を実行時に反映するには、root で起動してからアプリユーザーに降格する必要がある（要件定義 N-5）
- 選択肢: (a) gosu を GitHub リリースから取得して固定 (b) su-exec（Alpine 系、Debian には無い） (c) util-linux 同梱の setpriv
- 決定: (c)。Debian slim イメージに標準で入っており、追加の外部バイナリ取得・checksum 管理が不要
- 影響: なし

### D-002: ffmpeg は静的ビルドを checksum 検証して導入する

- 日付: 2026-08-08
- 背景: 要件定義 §4.2 で rclone / ffmpeg のバージョンを Dockerfile 内で明示固定することが求められている。apt 経由だと Debian リポジトリの状態に依存し、後から同じバージョンを再現できない
- 選択肢: (a) apt-get install ffmpeg （バージョン追跡が困難） (b) johnvansickle.com の静的ビルドを sha256 固定して取得
- 決定: (b)。取得 URL 自体は「最新の release」を指す固定文字列だが、ビルド時に sha256 を検証するため、上流が更新されればビルドが失敗して気づける（無言で異なるバイナリが混入しない）
- 影響: バージョンを上げる際は `FFMPEG_SHA256` を手動で更新する必要がある
- 補強（2026-08-08）: 取得 URL を `ARG FFMPEG_URL` として build-arg 化した。johnvansickle は最新版を固定名で配布し、旧版はバージョン番号付きファイル名で `old-releases/` 配下に残し続けるため、上流ローテーションで checksum 不一致が発生した場合は `old-releases/` の versioned URL に `FFMPEG_URL` を差し替えるだけで、以前と同一バージョンを再取得できる（イメージの再現性が壊れない）

### D-003: requirements.lock はこのセッションでは生成できていない

- 日付: 2026-08-08
- 背景: `pip-compile --generate-hashes` の実行には pip または Docker デーモンが必要だが、実装セッションの実行環境にはどちらも無かった（pip 未インストール、Docker Desktop の WSL 連携が無効）
- 決定: ハッシュを手で捏造しない。`make lock` ターゲット（Docker + ネットワークがある環境で pip-compile を実行）を用意し、ユーザー側での実行を前提とする
- 影響: `requirements.lock` が生成されるまで `docker compose up` は失敗する。AISTATE.md の未解決 #1 を参照

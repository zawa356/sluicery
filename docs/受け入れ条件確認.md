# 要件定義 §19 受け入れ条件確認

確認日: 2026-08-21

## 判定方針

- `PASS`: 条件どおりの実機操作、隔離Compose / SQLite / Storageでの統合確認、または同じ境界を通る自動試験で成立を確認した
- `FAIL`: 条件どおりに動作しなかった
- `NOT RUN`: 環境・権限・安全上の理由で確認していない
- 実URL、Cookie、資格情報、ホスト識別情報は記録しない
- 保存済みの実メディアを削除・移動する確認は行わず、必要な破壊系確認は合成fileと隔離DB / volumeだけで行った

確認環境は、Ubuntu 22.04 VMでの初期構築・SMB検証、WSL2上のDocker Compose、独立project / volume /
port / configを使う隔離Compose、コミット済み状態だけの隔離clone、Docker test imageである。実CIFS / NFSの
kernel `mount` adapterは環境制約により未検証だが、要件定義§19の26項目には含まれないため、
`docs/storage.md`と本書末尾の既知制限へ分けて記録する。

## 受け入れ条件外の既知制限

- `mount` Storageの実CIFS / NFS mount・読書き・再接続は未検証。通常Composeで無効、明示overlay時の
  capability継承、設定検証、補助command、合成delegationまでは確認済み
- Phase 8の実運用規模同期はdownloadedが大半になったが、HTTP 403と形式非互換のTargetが残り、
  配信元への追加負荷を避けて全件完走試験を停止した
- Proxmox LXCとNAS固有環境は未検証
- 公開repositoryのclone URL確定とGitHubへのpushは、公開前監査と利用者承認まで保留
